# 칭찬교환소 기획·운영안

2026년 11월 20일 업데이트 · 팀 내 공유용

## 브랜드 이름과 기획 의도

서비스의 이름은 **칭찬교환소**입니다.

‘교환’에는 두 가지 의미가 있습니다. 동료의 도움과 고마움을 칭찬으로 돌려주고, 분기 평가로 쌓인 개인 포인트를 원하는 보상으로 교환합니다. 같은 팀을 포함한 동료의 좋은 행동을 발견하고 개인이 보상을 선택하는 경험으로 연결합니다.

> **동료에게 받은 고마움, 칭찬으로.**
>
> **동료에게 받은 칭찬, 나를 위한 선물로.**

‘교환소’는 직원이 고마운 이야기를 맡기는 친근한 공간입니다. 엄지를 든 피플팀 마스코트를 **칭찬교환소 소장**으로 활용합니다.

| 접점 | 브랜드 표현 |
| --- | --- |
| Slack 앱·홈 | 칭찬교환소 |
| 참여 버튼·작성창 | 칭찬 맡기기 |
| 제출 버튼 | 비공개로 맡기기 |
| 접수 완료 | 고마운 마음, 잘 맡아뒀어요! 📮 |
| 분기 캠페인 | 이번 분기, 칭찬을 나를 위한 선물로! |
| 선물 카드 | 나에게 쌓인 칭찬포인트로 원하는 선물을 골라보세요. |

실제 도움에 대한 자발적 칭찬을 장려하며, 점수를 위해 미리 약속한 맞칭찬은 지양합니다. 분기 최종 순위에 따라 개인 포인트를 지급하고, 개인이 원하는 상품으로 교환합니다.

## 1. 서비스 개요

칭찬교환소는 Slack에서 동료의 좋은 행동을 비공개로 접수하고, 분기 평가를 통해 개인 포인트를 지급하는 사내 인정 서비스입니다.

**동료 칭찬 → 분기 마감 → 정량·정성 평가 → 최종 순위와 지급 예정 포인트 확인 → 피플팀 지급 승인 → 개인 포인트 적립 → 보상 교환**

칭찬은 제출 즉시 접수됩니다. 공개 채널 자동 게시와 수신자 자동 알림은 제공하지 않습니다. 지정된 피플팀 관리자는 작성자·수신자·본문을 확인할 수 있습니다.

| --- | --- |

현재 테스트 사이트가 보인다는 사실과 실제 직원의 보상 운영을 시작하는 시점은 구분해서 안내합니다. 자동 정산은 향후 목표이며 현재는 피플팀이 평가와 검토를 진행합니다.

## 3. 직원 사용 흐름과 Slack 홈

1. Slack 앱 홈에서 칭찬 맡기기를 누릅니다.
2. 동료 한 명, 핵심가치 하나, 구체적인 칭찬 내용을 입력합니다.
3. 본인 여부·동일 동료 분기 중복·활성 등록 계정을 확인하고 즉시 접수합니다.
4. 분기 종료 후 피플팀이 평가 결과와 포인트를 확인합니다.
5. 지급 승인 후 직원이 교환소에서 잔액과 상품을 확인하고 신청합니다.
6. 같은 페이지에서 교환 내역과 처리 상태를 확인합니다.

홈은 인사, 이번 분기 남긴 칭찬·받은 칭찬, 참여·교환 버튼, 참여 안내 순으로 구성합니다. 버튼은 가능한 한 한 행에 배치하고 바로고 주황색과 마스코트로 통일감을 줍니다. Slack 버튼 자체는 임의의 색상 코드 지정에 제한이 있습니다.

입력란 안내는 다음과 같습니다.

> 어떤 상황에서, 동료가 무엇을 어떻게 했고, 어떤 도움이 되었는지 적어주세요. 선택한 핵심가치와 연결되는 행동이 구체적으로 드러날수록 좋아요. 길이보다 내용이 중요해요!

칭찬 내용은 20~2,000자로 입력합니다. 받은 칭찬의 본문·작성자는 일반 직원에게 노출하지 않습니다. 홈의 발신·수신 건수는 접수 건수이며, 분기 평가 후 점수에 반영하는 유효 건수는 별도로 구분합니다.

## 4. 참여·접수 규칙

| 항목 | 운영 규칙 |
| --- | --- |
| 같은 팀·다른 팀 칭찬 | 모두 가능 |
| 월별 제출 횟수 | 월 1회 |
| 동일 동료 중복 | 작성자 → 수신자 조합별 분기 1회 |
| 서로 칭찬 | 실제 고마운 행동이 있으면 A→B와 B→A 각각 가능 |
| 분기 변경 | 다음 분기에 같은 동료에게 다시 가능 |
| 본인 칭찬 | 불가 |
| 참여 대상 | 활성 등록 직원, Slack ID 기준 |
| 접수 승인·반려 | 제출 즉시 접수 완료 |
| 공개 채널 게시·수신자 자동 알림 | 제공하지 않음 |

월 한도는 평가 전 접수 이력 기준입니다. 부실한 칭찬으로 0점을 받아도 해당 월의 제출 한도를 사용합니다.

분기는 한국 시간 1~3월·4~6월·7~9월·10~12월입니다. 같은 분기에는 핵심가치를 바꿔도 같은 동료에게 다시 제출할 수 없습니다. 재전송과 동시 제출도 중복 접수를 막아야 합니다.

안내 문구는 “같은 동료에게는 분기당 한 번만 칭찬할 수 있어요. 더 다양한 동료의 좋은 행동을 발견하기 위한 규칙이에요. 실제로 고마웠던 일이 있다면 서로 칭찬해도 괜찮아요. 점수를 위해 미리 약속한 맞칭찬은 지양해주세요.”를 사용합니다.

## 5. 직원·조직 정보 관리

직원은 Slack ID로 식별합니다. 피플팀 CSV의 직원 정보를 Supabase 직원 테이블에 반영하고, 이름·조직·활성 여부를 관리합니다. 원본 CSV와 현재 DB 명부는 별도로 관리합니다.

| 컬럼 | 용도 |
| --- | --- |
| slack_user_id | 계정 연결·동일인 구분 |
| name | 직원 이름 표시 |
| part1 | 참고 상위 조직 |
| part2 | 상위 조직, 운영 조회·분석 참고 |
| part3 | 팀·직속 조직, 운영 조회·분석 참고 |
| 연결상태 | 당시 계정 연결 결과, 현재 재직·활성 상태와 구분 |

조직이나 조직 정보 누락으로 칭찬을 차단하지 않습니다. 입·퇴사·전배 시 명부와 관리자 권한을 갱신합니다. CSV에서 빠졌다는 이유만으로 자동 퇴사 처리하지 않고 상태를 확인합니다.

## 7. 피플팀 비공개 접수함

관리자는 **진명희·안병기·박혜원·김정주·김동현A** 다섯 명입니다. 김동현A는 확인한 ‘김동현(피플팀)’ 계정으로 연결합니다. 권한은 Slack ID로 확인합니다.

관리자는 전체 접수와 본인 발신·수신 건도 조회할 수 있습니다. 접수는 조회 전용이며, 내용 판단은 분기 평가에서 진행합니다. 접수함은 최신순 5건씩 보고 다음 5건·처음으로 이동할 수 있습니다. 전체 분석은 CSV를 사용합니다.

| 사용자 | 접근 범위 |
| --- | --- |
| 일반 직원 | 칭찬 접수, 본인 건수·잔액·교환 내역 |
| 지정 피플팀 관리자 | 직원 기능과 전체 접수·CSV·평가·정산·상품·주문·잔액 관리 |
| DB 운영 권한자 | 명부·권한 설정과 삭제 등 운영 작업 |

칭찬 접수는 즉시 완료됩니다. 분기 정산의 포인트 지급은 피플팀 승인 후 이루어집니다.

## 8. CSV 내보내기와 보관

비공개 접수함에서 CSV를 내보냅니다. 화면의 5건이 아닌 보존 중인 전체 접수가 대상이며 귀속월로 분기를 선택합니다.

CSV는 접수번호, 접수일시(KST), 귀속월, 접수상태, 작성자, 작성자 Slack ID, 작성자 조직, 받은 동료, 수신자 Slack ID, 수신자 조직, 핵심가치 코드, 핵심가치 표시명, 칭찬 내용의 13개 열입니다.

한글·줄바꿈·따옴표를 보존하고 수식으로 실행될 수 있는 값을 방어합니다. 기존 다운로드 링크는 5분간 1회 사용하는 방식이며 관리자 권한을 확인합니다. 피플팀의 승인된 저장 위치에서 파일을 관리합니다. DB 삭제 후에도 내려받은 파일은 별도로 삭제해야 합니다.

## 9. 분기 평가와 점수

### 9.1 평가 자료와 유효 칭찬

귀속월로 분기를 판단하고 Slack ID와 접수번호로 집계합니다. 동일 접수번호의 동일 행은 한 건으로 계산합니다. 과거 승인·반려·대기 상태를 제외 조건으로 쓰지 않습니다. 피플팀이 따로 지정한 테스트·무효 건은 구분합니다.

최신 확정 기준은 **접수 이력과 점수에 반영하는 유효 건수를 구분**하는 방식입니다. 평가 전에 아래 두 기준을 확인합니다.

1. 실제 행동을 식별할 수 있는가. 감사 표현이나 성향만 나열하면 해당 건을 0점으로 기록합니다.
2. 행동이 선택한 핵심가치에 부합하는가. 아래 ‘행동의 가치 부합’ 항목이 30점 중 8점 미만이면 해당 건 전체를 0점으로 기록합니다.

위 기준에서 0점인 건은 접수 이력에 남기고 작성자·수신자 양쪽의 정량 유효 건수와 수신자의 정성 평균에서 제외합니다. 기준을 통과했지만 설명이 부족한 건은 근거에 따라 낮게 채점하고 평균에 포함합니다. 다른 가치가 더 잘 맞더라도 저장된 가치를 임의로 바꾸지 않습니다.

ID 충돌·알 수 없는 가치 코드 등으로 평가할 수 없는 건은 보류합니다. 해결 전 관련 점수와 순위를 잠정으로 표시합니다. 기존 정량 화면의 접수 집계와 분기 평가 후 유효 집계를 혼동하지 않도록 이름을 구분합니다.

### 9.2 정량 점수

**정량 점수 = MIN(100, 유효 수신 건수 × 5 + 유효 발신 3건 이상이면 5)**

발신 보너스는 분기당 한 번입니다.

| 유효 수신 | 유효 발신 | 정량 점수 |
| --- | --- | --- |
| 9건 | 3건 | 50점 |
| 9건 | 2건 | 45점 |
| 0건 | 3건 | 5점 |
| 20건 | 3건 | 원점수 105점, 상한 적용 100점 |

막연한 칭찬만 3건 보냈다면 유효 발신은 0건이며 발신 보너스도 0점입니다. 최고점 대비 재환산은 하지 않습니다.

### 9.3 정성 점수

| 평가 영역 | 배점 | 하위 항목 |
| --- | --- | --- |
| 행동의 구체성 | 35점 | 상황·맥락 10, 실제 행동 20, 당사자 기여 5 |
| 선택한 핵심가치 부합성 | 45점 | 행동의 가치 부합 30, 연결 설명 15 |
| 도움·변화의 설명 | 20점 | 도움·변화 10, 행동과 효과 연결 10 |

일곱 항목을 1점 단위 정수로 채점합니다. 본문에 확인되는 근거와 감점 이유를 기록하고, 95점 이상은 근거를 다시 점검합니다. 100점은 모든 만점 요건을 충족할 때 부여합니다. 강제 점수 분포나 만점 인원 제한은 두지 않습니다.

글 길이·문장력·직급·직무의 인상·화려한 수치는 가점 요소가 아닙니다. 짧아도 행동과 도움이 충분하면 높은 점수를 받을 수 있습니다. 정확한 날짜·장소·매출은 필수 조건이 아닙니다. 기대 효과와 실제 관찰된 도움을 구분합니다.

직원별 정성 점수는 **받은 유효 칭찬의 건별 점수 평균**입니다. 유효 수신이 없어 평균을 낼 수 없으면 ‘평가 근거 없음’으로 표시합니다. 평가 건수·최저·최고·서로 다른 작성자 수와 대표 사례도 함께 제공합니다.

### 9.4 최종 점수와 순위

**최종 점수 = 정량 점수 × 50% + 정성 평균 × 50%**

유효 수신 9건·유효 발신 3건이면 정량 50점입니다. 정성 평균이 80점이면 최종 65점입니다. 정량·정성·최종 순위를 각각 제공합니다. 비교는 반올림 전 값, 최종 표시는 소수점 둘째 자리입니다. 공동 순위는 1·2·2·4처럼 다음 순위를 건너뜁니다. 정성 근거가 없으면 최종 점수와 지급을 보류합니다.

## 10. 분기 정산과 피플팀 운영

1. 분기 종료 후 전체 접수 CSV와 평가 프롬프트 v3.1을 준비합니다.
2. 모든 접수를 건별 판정하고 유효 수신·발신과 정성 평균을 계산합니다.
3. 정량·정성·최종 순위, 예정 포인트, 공동 순위, 제외·보류 건을 확인합니다.
4. 피플팀이 누락·계산·평가 근거와 지급 총액을 검토합니다.
5. 확정 결과를 정산에 반영하고 지정 관리자가 지급을 승인합니다.
6. 직원별 잔액과 적립 내역을 확인하고 교환 신청을 처리합니다.

지급 승인 전 예정 포인트는 사용할 수 없습니다. 동일 정산의 재승인·재시도도 중복 적립을 막습니다. 보류·실패는 0점으로 대체하지 않습니다. 일부 평가가 보류되어 결과가 달라질 수 있으면 먼저 확인합니다.

자동 분기 마감·AI 실행·재시도·차액 정정은 향후 자동화와 운영 연결에서 검증할 항목입니다. 현재는 피플팀이 평가를 실행하고 확인합니다. 지급 후 점수 변경·이의신청 기간과 차액 반영 절차는 운영 시작 전에 정합니다.

## 12. 개발 구조와 실행

Slack은 칭찬 접수·현황·교환소 버튼을, 웹은 잔액·상품·교환 내역을 담당합니다. 서버가 사용자 권한과 점수·지급·차감을 확인하고 거래 원장으로 잔액을 계산합니다.

현재 프로젝트 폴더는 `C:\Users\bkahn\Desktop\AX\03 BAROGO THANKYOU`입니다. 저장소는 https://github.com/barogo-bkahn/BAROGO-THANKYOU 이며, Slack 테스트 버튼은 http://10.10.20.31:5000 으로 연결됩니다.

해당 폴더에서 `npm run exchange:demo`로 테스트 서버를 켜고 Ctrl+C로 끕니다. 백그라운드 서버가 이미 실행 중이면 먼저 종료합니다. 같은 사내망에서 접속하며 PC IP가 바뀌면 서버 설정과 Slack 버튼 주소를 함께 바꿉니다.

실제 직원용 운영에는 로그인·활성 직원·피플팀 권한·운영 DB·정산 반영을 확인해야 합니다. 데모 명부와 잔액은 가상 데이터입니다.

## 13. 평가 테스트용 가상 데이터

이번 자료는 **2026년 3분기 50건**입니다. ‘3/4분기’는 3분기인 7~9월로 해석했습니다. 모든 인물·조직·Slack ID·상황은 가상입니다. 운영 DB에는 넣지 않고 CSV로 제공합니다.

구체적인 행동과 결과, 짧지만 명확한 칭찬, 행동은 있으나 효과가 모호한 칭찬, 감사·성향 위주의 칭찬, 길지만 행동이 없는 칭찬, 선택 가치와 행동이 어긋나는 칭찬을 섞었습니다. 같은 팀, 작성자별 월 1회 발신, 서로 주고받은 칭찬, 특정 동료에게 수신이 몰린 사례도 포함합니다. 모든 행은 정상 접수 형식으로 만들고, 동일 방향 분기 중복·본인 추천은 넣지 않습니다.

정답 점수와 유효 여부는 CSV에 넣지 않았습니다. 먼저 프롬프트로 평가한 뒤 건별 판정과 근거가 적절한지 확인합니다. 50건은 접수 건수이며, 유효 건수와 점수 합계는 평가 결과에 따라 달라집니다. 과거 50건 자료의 정답 합계나 승인·반려 비율은 이번 자료에 적용하지 않습니다.

## 14. 관련 자료와 테스트 방법

이 페이지 하단에 평가 프롬프트 v3.1 전체를 수록합니다. 함께 첨부한 가상 CSV와 프롬프트 파일을 평가 도구에 제공합니다.

실행 요청은 다음과 같이 작성합니다.

> 첨부한 평가 프롬프트 v3.1으로 가상 칭찬 50건 CSV 전체를 평가해줘. 평가 분기는 2026년 3분기, 추천 인원은 10명이야. 건별 판정과 일곱 항목 점수, 유효 발신·수신, 정량·정성·최종 순위, 지급 예정 포인트, 검산 결과를 모두 제공해줘. 원본 접수번호와 연결해서 확인할 수 있게 해줘.

먼저 총 50건을 읽었는지 확인합니다. 이어 막연한 칭찬·가치 불일치 판정, 발신 보너스, 상한, 정성 평균, 50:50, 공동 순위와 포인트를 검토합니다. 프롬프트는 접수번호별 근거와 결과 CSV·JSON 형식을 포함합니다.

## 15. 칭찬포인트와 교환 상품

### 지급 기준

| 1위 | 30,000P |
| 2~3위 | 25,000P |
| 4~5위 | 20,000P |
| 6~10위 | 10,000P |
| 10위 밖 | 0P |

공동 순위는 같은 포인트를 받습니다. 정성 근거가 없어 최종 점수를 낼 수 없는 직원은 지급 보류입니다. 순위별 포인트를 사용하며 평가 점수에 일률적인 환산율을 곱하지 않습니다.

남은 포인트는 다음 분기로 이월되고 **각 지급일부터 1년까지 유효**합니다. 1년이 지난 미사용 포인트는 소멸합니다. 현재 잔액 계산에서 자동 소멸 동작은 완료 확인이 필요합니다. 사용 차감 순서, 취소 환불 시 원래 유효기간 적용, 퇴사 시 잔액 처리도 운영 시작 전에 정합니다.

### 교환 화면과 주문

직원 화면은 한 페이지에서 잔액·상품·교환 확인·내 신청과 적립 내역을 제공합니다. 포인트 부족과 품절을 안내하고, 확인 후 포인트 차감과 주문 생성을 함께 처리합니다. 같은 요청 재전송과 동시 주문도 중복 차감이나 잔액 초과를 막아야 합니다.

현재 주문은 신청·지급 완료·취소 상태를 관리합니다. 신청 시 포인트가 차감되고, 피플팀이 실제 전달이나 휴가 부여를 확인해 완료 처리합니다. 재고는 완료 시 차감합니다. 수량 부족 등으로 처리할 수 없으면 취소·환불합니다. 완료 후 사후 환불은 별도 운영 절차를 정합니다.

### 피플팀 총괄 화면

피플팀은 분기 점수·순위·예정 포인트·지급 승인, 전 직원 잔액, 상품·수량·노출 여부, 전체 주문과 완료·취소 이력을 확인합니다. 현재 관리 화면에 제공되는 조회·CSV를 활용하고, 향후 추가할 검색·필터·차액 정정은 구현 여부를 확인해 안내합니다.

승인 전 예정 포인트 사용 불가, 중복 지급 방지, 개인·총괄 잔액 일치, 신청 차감·취소 환불 일치, 관리자 권한을 운영 전 검증합니다.

### 팀원 설명용 소개

> 칭찬교환소는 동료의 좋은 행동을 Slack에서 비공개로 남기고, 분기 평가 순위에 따라 받은 개인 포인트로 원하는 선물을 고르는 서비스입니다. 같은 팀도 칭찬할 수 있고 월 1회 제출할 수 있으며, 같은 동료에게는 분기당 한 번 보낼 수 있습니다. 피플팀이 분기 평가 결과와 포인트 지급을 확인하고 교환 신청을 처리합니다.
