# 칭찬교환소 웹 MVP

직원 화면: 잔액·상품·교환 확인 모달·주문·거래·분기 정산 내역을 한 페이지에서 제공.
피플팀 화면: 전 직원 정산·지급 승인·잔액·주문·처리·취소 환불·CSV를 한 페이지에서 제공.

## 지금 실행

Node 24에서 저장소 루트 기준 `npm run exchange:demo`. 외부 패키지 설치는 필요하지 않습니다.
주소: http://127.0.0.1:5000

로그인 화면의 피플팀 관리자로 둘러보기 / 직원으로 둘러보기를 사용합니다. 모든 인물·잔액·상품·점수는 가상입니다. 테스트 가격 및 환산율은 실제 운영 정책이 아닙니다. 파일 DB는 exchange/.data/demo.sqlite에만 저장되며 운영 Supabase와 연결되지 않습니다. 서버를 재시작해도 상태가 남습니다. 테스트 쿠폰·휴가는 실제 지급되지 않습니다.

빠른 테스트:
1. 피플팀 관리자로 로그인 → 피플팀 관리 → 미지급 분기를 선택하고 순위·지급 예정 포인트를 확인합니다. 지급 완료된 과거 분기는 기존 기록을 유지합니다.
2. 정량 50% + 정성 50%의 최종 점수로 순위를 정합니다. 현재 제안은 1위 30,000P, 2~3위 25,000P, 4~5위 20,000P, 6~10위 10,000P입니다. 피플팀 승인 후 잔액에 적립됩니다.
3. 내 교환소 → 반차 30,000P 또는 스타벅스 카드 10,000P 교환 → 해당 포인트 차감과 새 주문 처리 중 상태를 확인합니다.
4. 피플팀 관리 → 전체 교환 내역에서 지급 완료 또는 취소·환불. 취소 시 포인트·재고가 한 번만 복구됩니다.
5. 직원 민서로 로그인하면 관리자 전환 및 총괄 API 접근이 차단됩니다.

기본 가상 직원 4명 중 1명은 수신 없음으로 정성 근거·지급이 보류됩니다. 관리자 재승인은 이중 적립하지 않습니다. 거래 원장 합계와 관리자 전체 잔액이 일치해야 합니다.

2026-11-04 개편: 6개 카테고리, 20개 상품을 로컬 데모에 적용했습니다. 마우스·키보드 세트와 모니터 보안필름은 각각 50,000P입니다. 2~3위 2회 또는 4~5위 3회 적립으로 교환할 수 있습니다. 공동 순위는 같은 포인트를 받고 다음 순위는 건너뜁니다. 10위 밖 순위 포인트는 0P인 제안입니다. 잔액은 분기 간 이월됩니다. 상품 모델과 1위 외 지급 구간은 운영 전 확정해야 합니다.

이 개편은 로컬 데모에 적용했습니다. 아래 운영 PostgreSQL 초안과 stage.mjs의 기존 점수 환산 절차는 새 순위 정책으로 이관·검증하기 전 운영에 적용하지 않습니다. 실제 직원 지급이나 휴가 부여는 발생하지 않았습니다.

## 구현과 운영 연결 상태

- 로컬 SQLite 기반 사이트: 로그인·승인·적립·교환·재고·완료·환불 저장 및 서버 권한 검증 구현.
- 운영 서버: Slack OIDC 서명 검증·워크스페이스·직원 검증·8시간 HttpOnly 세션·CSRF·서버 전용 Supabase RPC 어댑터 구현.
- db.sql: 기존 thankyou 직원/관리자/칭찬 테이블을 이용하는 운영 PostgreSQL 확장 초안. RLS와 service_role 전용 SECURITY INVOKER RPC. 실제 운영 DB 미적용, PostgreSQL 실행 검증 미완료.
- Supabase 도구가 권한 오류를 반환하여 실제 DB 연결·배포·Slack CTA 활성화는 이번 실행에서 완료하지 못했습니다.
- 사이트는 확정된 평가 결과를 정산·승인·사용하는 부분입니다. AI 자동 평가 호출·분기 예약 실행·공급사 쿠폰 발급·휴가 시스템 연동은 아직 구현되지 않았습니다. 상품 전달 후 관리자가 지급 완료로 변경하는 MVP입니다.
- 원래 Slack 앱의 월별·조직 제한 제거는 별도 배포 필요입니다. 이 웹 서버가 기존 제출 API의 규칙을 바꾸지는 않습니다.

## 운영 배포 절차

1. 접근 복구 후 기존 스키마를 재확인하고 exchange/db.sql을 검증한 후 마이그레이션으로 적용합니다. anon/authenticated 실행 권한이 없는지, service_role에서만 RPC가 실행되는지 점검합니다. DB advisors를 실행합니다.
2. exchange/.env.example을 기준으로 서버 비밀을 설정합니다. EXCHANGE_SESSION_SECRET는 32자 이상 무작위 값. 공개 URL은 HTTPS, 루트 경로 사용. 서비스 키는 브라우저에 제공하지 않습니다. 실제 명부는 기존 DB를 사용하며 가상 데이터는 올리지 않습니다.
3. Slack 앱 OAuth Redirect URL에 `https://실제도메인/auth/callback`을 추가합니다. 사이트는 설치 OAuth와 분리된 `openid` 흐름을 사용합니다. JWKS RS256·issuer·audience·expiry·nonce·team을 검증합니다. HTTPS 쿠키를 위해 프록시에서 TLS 종료합니다.
4. 기존 서버와 별도로 `npm run exchange:start` 또는 저장소 루트에서 `docker build -f exchange/Dockerfile -t thankyou-exchange .` 후 비밀을 주입하여 배포합니다. 서버는 정적 파일과 API를 같은 출처에서 제공합니다.
5. 상품 가격·포인트 환산율을 확정한 후 실제 상품을 exchange_products에 등록하고 active=true로 설정합니다. 기본 상품/환산율은 운영 DB에 시드하지 않습니다.
6. 평가 프롬프트 v2.1의 7개 정수 점수를 모두 준비해 stage.mjs로 적재합니다. JSON은 quarter(2026-Q3 형식), rate(확정 환산율), prompt_version, evaluations 배열을 포함하며 각 항목은 praise_id와 scores 7개입니다. 분기·전체 접수 커버리지·중복·배점 검증 실패 시 전체 롤백됩니다. 정량 건수는 DB에서 직접 계산합니다. 이미 정산된 분기는 덮어쓰지 않습니다. 운영 중 테스트 건이 포함되지 않도록 시행 전에 데이터 범위를 확인해야 합니다.
7. 피플팀이 해당 분기 지급 승인 버튼을 눌러 적립합니다. 지급은 분기 정산과 하나의 트랜잭션으로 완료되며 재요청은 중복 지급하지 않습니다. 승인 후 정정·차액 원장 UI는 후속 범위입니다.
8. 실제 HTTPS 사이트를 확인한 뒤 기존 Slack 서버의 EXCHANGE_PUBLIC_URL에 같은 주소를 설정하고 최신 소스를 배포하면 앱 홈의 교환 CTA가 표시됩니다. localhost 데모 URL은 직원용 Slack에 넣지 않습니다.

보존: 기존 칭찬 원본365일 정책을 그대로 확장해 포인트 원장을 삭제하지 않습니다. 포인트 유효기간은 **지급 후 1년**으로 정했습니다(소멸 처리는 아직 구현 전). 포인트·주문·휴가의 별도 보존 기간, 퇴사·잔여 포인트·환불 기준은 확정해야 합니다. 현재 MVP에는 배송지 수집·직원간 양도·현금 출금·팀 선물이 없습니다.

테스트 초기화: 저장소 루트에서 node exchange/reset-demo.mjs 실행 후 새로고침. 가상 직원만 있는 로컬 demo.sqlite에만 적용됩니다.

## 개발 DB (Supabase dev 프로젝트)

- 개발: `barogo-thankyou-dev` (ref `uzyicrlvtievfkylzqek`, 도쿄). 운영 `xzyummywoqfvyhdnoyeb`에는 교환소 테이블을 만들지 않았습니다.
- 적용 순서: `db/schema.sql` → `exchange/db.sql`(rank_v2 정책) → `exchange/seed-dev.sql`(가상 직원·상품·분기 이력, `make-seed-dev.mjs`로 생성). seed-dev.sql은 개발 전용이며 운영에 실행하지 않습니다.
- 개발 DB로 화면 실행: `node --env-file=exchange/.env.dev exchange/demo.mjs` → http://127.0.0.1:5000 (`.env.dev`는 서비스 키가 있어 공유·커밋 금지). `EXCHANGE_DEV_PROJECT_REF`와 `SUPABASE_URL`이 일치하는 프로젝트에서만 데모 로그인이 허용됩니다.
- `$$`가 포함된 SQL을 `supabase db query -f`로 적용하면 잘려서 실패하므로 `$body$` 같은 태그 인용으로 바꾼 사본으로 실행했습니다.

## 지급 이력 상세 근거

- 피플팀 관리 → 분기별 지급 이력 → 분기 펼치기 → 대상자 행의 "정량·정성 근거 보기"를 누르면 그 사람의 근거 창이 열립니다.
- 정량: 그 분기에 받은·보낸 칭찬 목록과 판정(구체적 / 막연한 칭찬 / 가치 부합 없음), 판정별 점수 반영, 정량 원점수 계산.
- 정성: 받은 칭찬별 7개 하위 점수·합계·판정 근거·본문, 평균 계산(막연한 칭찬은 평균에서 제외), 최종 점수.
- 데이터는 관리자 API의 `evidence`(건별 평가)에서 옵니다. 운영에서는 `exchange_evaluations`의 `gate`·`note` 열에 평가 결과를 적재해야 합니다.

## 선물 관리 (피플팀)

- 피플팀 관리 → "선물 관리" 탭에서 선물을 등록하고 이름·카테고리·이미지·교환 포인트·남은 수량·이용 안내·노출 여부를 수정합니다. 삭제는 없고 "교환소에 노출"을 끄면 직원 화면에서 숨겨집니다(과거 교환 내역 보존).
- 가격을 바꿔도 이미 신청된 교환에는 영향이 없습니다(신청 시점의 이름·포인트가 기록됨). 남은 수량은 지급 처리 때 1개씩 차감되고, 이 화면에서 직접 고칠 수도 있습니다.
- 서버가 입력을 검증합니다: 이름 1~40자, 카테고리 5종, 포인트 1~1,000,000 정수, 수량 0~9,999 정수, 안내 200자 이하. 변경은 감사 기록(`product_create` / `product_update`)에 남습니다.
